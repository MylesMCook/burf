Berth connects a laptop to any number of development machines (a VPS, a
cloud VM, a desktop under your desk) and gives each repository on them
worktrees, terminals, agents, dev servers and automations. The agents run on
the boxes, so closing the app, sleeping the laptop or losing Wi-Fi never
stops them; the app is a view you can close and reopen at any time.

<Stage title="Get started">

```sh
git clone https://github.com/sean-brydon/berthd
cd berthd && make all
bin/berth add ssh me@my-box --name my-box
```

Berth has no release yet, so you build it from source. The last line
installs `berthd` on your box over SSH, starts it and pairs your laptop with
it; one more line on the box
[lets agents report their state](/getting-started/first-agent#let-the-box-report-agent-state).
Once the first release is out, a box will take one line
(`curl -fsSL https://berthd.app/install | sh`). Every step is in
[install](/getting-started/install).

</Stage>

## What it does

- **Workspaces per worktree.** Terminals, splits, and browser tabs onto each
  worktree's dev server, at private URLs like
  `http://billing.cal.devl.localhost:1377/`.
- **Agents you can see and steer.** Claude Code, Codex and others, with a
  dashboard of who needs you, a review inbox for finished work, and
  [orchestration](/guides/orchestration) (prompt, wait, check, loop, hand off)
  from the app, the CLI, or other agents.
- **Projects set up the same everywhere.** Each worktree gets its own ports,
  environment, services, hooks and flows, from the repository's
  [`.berth/config.json`](/guides/project-config), a shareable
  [kit](/guides/kits), or the box's own config.
- **Automations.** [Flows](/guides/automations) on events, schedules or GitHub
  activity, running on the box; plus plain shell [hooks and gates](/guides/hooks).
- **Plugins.** [React plugins](/guides/plugins) for the app, with built-ins
  for git changes, pull requests, dev servers, box monitoring, activity and
  notes.
- **Boxes without the fuss.** Pinned mutual TLS, pairing by link, boxes on
  other tailnets, self-upgrade over Berth's own connection, and a
  [phone companion](/guides/phone) served by each box.

## The pieces

| Piece | What it is |
| --- | --- |
| `berthd` | The daemon on each box: worktrees, sessions (tmux), services, hooks, flows, kits. |
| `berth` | The laptop CLI and background agent: connections, private URLs, the app's API. |
| `app/` | The desktop app (Tauri, React, coss ui). |
| `plugins/` | Built-in plugins, written against `packages/plugin-sdk`. |
| `kits/` | Kits, such as `cal-com`. |

Read [how Berth works](/concepts/architecture) for the whole picture, or
[the security model](/concepts/security) before you pair a box you care
about.
