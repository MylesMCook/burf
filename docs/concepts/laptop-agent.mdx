---
title: The laptop agent
description: The background process that holds every box connection, serves private URLs, and outlives the app.
---

The **Shipyard agent** (`berth agent`) runs on your laptop in the background. It
holds a connection to every paired box, runs saved forwards and the
`*.localhost` proxy, and serves a local API that the CLI and the desktop app
are clients of. Closing the app, or the app crashing, never stops a session,
a forward or a queued prompt.

## What it does

- keeps one pinned TLS connection per box, reconnecting forever, with health
  pings to notice a connection that died silently and sleep detection. A
  box that stops answering is tried again after about 2 seconds, then 4
  and every 8, each give or take 20% so boxes don't all retry at once; a
  request that waits 5 seconds for an answer has the box checked at once,
  and a request for a box known to be away is answered straight away
  instead of waiting out a dial ([Slow and dropping networks](#slow-and-dropping-networks));
- serves **private URLs** on port 1377, `http://3000.devl.localhost:1377/`,
  and runs **forwards** (a fixed local port to a box port) and **routes**;
  a box's URLs work by the name you paired it as and by the box's own name
  (see below);
- relays every online box's **events**, so laptop hooks, plugins and the app
  hear about every agent on every box;
- runs **laptop hooks** from `~/.berth/hooks.json`;
- holds the [offline prompt queue](/guides/offline-queue) and delivers it
  when boxes come back;
- runs an embedded Tailscale node for each [other tailnet](/getting-started/add-a-box#boxes-on-another-tailnet);
- keeps your **kits** library and serves your themes, task templates and
  plugins to the app.

## A box's own name

You name a box when you pair it (`devl`), and the box has a name of its own
(`devbox`, its hostname). URLs the box makes, such as `$BERTH_URL` or an
app's configured origin, use its own name: `http://checkout.shop.devbox.localhost:1377`.
The proxy accepts both, so a link an agent prints opens on your laptop, and
on a new computer that paired the box under another name. It learns each
box's own name when the box comes online, and skips a name that is also one
of your paired boxes or that two boxes share. The app's browser tabs show
either by your name for the box.

A server's redirect to its own `localhost:PORT` goes back to the address you
opened, and one to another port on the box's loopback (an auth server on
`localhost:4000`) goes to that port's name, `http://4000.devl.localhost:1377`,
since `localhost` there means the box, not your laptop.

## Running it

Any command that needs the agent starts it, and when the desktop app finds
it isn't running, it offers to: **Start the Shipyard agent** runs
`berth agent start`, and ticking **Start at login** installs it as a service
instead. To have it start at login and restart after a crash from a
terminal:

```sh
berth agent install      # launchd on macOS, a systemd user unit on Linux
berth agent status
berth agent uninstall
berth agent              # run it in the foreground instead
berth agent restart      # restart it once its work under way is done
berth stop               # stop it, and every forward
```

The agent outlives the app, so an update to Shipyard would leave it running
the old version. The updated app restarts it as it starts (`berth agent
restart --if-stale`), whether the app started it or it starts at login:
the agent first finishes what it's doing (adding or upgrading a box,
setting up this Mac's box, sending a queued prompt), and agents' sessions
keep running on their boxes throughout. The new agent then brings this
Mac's box up to date.

```sh
berth status             # boxes, forwards and the proxy at a glance
berth events             # every event from this laptop and every box, live
berth doctor             # what's wrong on this computer, and how to fix it
```

## How things reach it

| Client | How |
| --- | --- |
| The CLI | A Unix socket, `agent.sock`, in the state directory |
| The desktop app and plugins | `http://127.0.0.1:1378` with a bearer token; see [the app's API](/reference/app-api) |
| Your browser | `http://*.localhost:1377/`, the proxy |

## Where it keeps things

State is in `~/Library/Application Support/berth/client/` on a Mac and
`~/.config/berth/client/` on Linux (`$BERTH_HOME` moves it): its identity,
paired boxes, forwards, routes, the queue, logs and the app's token. Things
you write by hand are in `~/.berth/` (`$BERTH_USER_DIR` moves it): hooks,
task templates, themes, plugins, kits. The full list is in
[files and environment](/reference/files).

trust each other.

## Slow and dropping networks

Boxes are often far away (100–900 ms over Tailscale), and links drop. What
you see when one does:

- **Reconnecting to devl… Next try in 6s.** A terminal, a chat and a team
  setup in progress say the box is away, count down to the agent's next
  try, and offer **Try now**. The session keeps running on the box; the
  terminal comes back as it was, and the chat and the setup catch up from
  the box's events, which the agent asks for from the last one it saw.
- **Waiting for devl to answer…** Typing in a terminal that gets nothing
  back for 4 seconds says so (what you type may not arrive while the link is
  down), and has the agent check the box now.
- **devl isn't answering.** A read that has no answer in 30 seconds (⌘P,
  the Files panel, a diff) fails with that, rather than spinning, and asks
  you to try again in a moment.
- A message sent again after the link dropped its answer carries the same
  idempotency key, so the box types it once.
- The app's own connection to the agent (its event stream) is dropped and
  opened again if it is silent for 45 seconds, as after the laptop sleeps,
  with a jittered backoff, and refetches what changed; refreshes that land
  together run as one.
