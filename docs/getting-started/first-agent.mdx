## Let the box report agent state

Berth knows whether an agent is working, waiting for you or done from the
agents' own hooks, installed on the box where the agents run. `berthd
install` (which `berth add ssh` and the install script run) installs them for
every agent CLI it finds on the box, and says so:

```text title="Example output"
Agent integrations (hooks for needs-you, working and done; berth's skills):
  Claude Code: skills in /home/me/.claude/skills; hooks added in /home/me/.claude/settings.json
  Not found: Codex, Cursor Agent. After installing one, run: /home/me/.local/bin/berthd integrations install codex|cursor
```

An agent you install on the box later has none. The first time the app starts
it there, it offers to install them (**Install Claude Code's hooks on
my-box**). Or run, from the laptop:

```sh
ssh me@my-box '~/.local/bin/berthd integrations install claude'
```

Use `codex`, `cursor` or `all` for other agents. For Codex this sets
`notify` in `~/.codex/config.toml`, unless you already use it for something
else; then it prints the line to change yourself. The full path matters: a
command over SSH may not have `~/.local/bin`, where berthd lives, on its
`PATH`. To skip all this, install with `--no-integrations`.

This also installs Berth's [skills](/guides/agent-integrations#skills), so
agents on the box know how to use Berth themselves. The hooks record
berthd's full path, so they work whatever `PATH` the agent has. Without them
an agent still runs; Berth just can't tell what state it is in (apart from
Claude Code's "trust this folder" question at startup, which it spots on the
screen).

## Start a task

A **task** is a worktree with an agent already running in it, made in one
step:

```sh
berth task new my-box/app/fix-login --agent claude --prompt "Fix the login redirect"
```

| Flag | What it does |
| --- | --- |
| `--agent ID` | Which agent: see `berth agents my-box` for what the box can start |
| `--prompt TEXT` | Its first prompt |
| `--branch B`, `--base REF` | As for `worktree new` |
| `--open split\|tab` | Ask the app to show the new agent: in its worktree when you are looking at it, otherwise as a notice that opens it |

The built-in agents, offered when their command is installed on the box:

| ID | Agent | Command |
| --- | --- | --- |
| `claude` | Claude Code | `claude` |
| `codex` | Codex | `codex` |
| `opencode` | OpenCode | `opencode --prompt …` |
| `gemini` | Gemini CLI | `gemini -i …` |
| `cursor` | Cursor Agent | `cursor-agent` |

A repository can add its own or replace these in
[`.berth/config.json`](/reference/config#agents).

To start an agent in a worktree that already exists, or a plain shell:

```sh
berth session new my-box/app/fix-login --agent codex --prompt "Review the diff"
berth session new my-box/app/fix-login              # a shell
```

## Watch it

```sh
berth sessions my-box                  # every session, with its agent's state
berth session screen my-box/SESSION    # what it shows right now
berth attach my-box/SESSION            # take over this terminal; Ctrl-b d detaches
```

Sessions run in tmux on the box. Detaching, closing the app or sleeping the
laptop leaves them running.

In the app:

- **Agent Dashboard** (⌘J) shows every agent on every box by what it needs:
  **Needs you**, **Working**, **Done**, **Ready**.
- **Review** lists agents' finished work, to approve, send back or discard.
- A notification tells you when an agent is waiting for you.

The sidebar starts with **Home** (the Agent Dashboard, or the harbour home
with [Labs](/guides/labs)), **Review**, **Worktrees** and **Automations**.
Everything else, Kits and plugins' screens included, is under **More**;
right-click a place, or use **Customize sidebar…**, to pin, move or hide it.
**Help → Keyboard shortcuts** (⌘/) lists every shortcut. In the Mac app
they are in the menu bar too, under File, View, Go and Help.

## Steer it

```sh
berth session send my-box/SESSION "Now add a test for it" --wait
berth loop my-box/SESSION --check "pnpm test" --prompt "Make the tests pass"
```

`send --wait` returns when the turn it starts ends. `loop` prompts, waits,
runs the check in the worktree and sends failures back until it passes. More
in [orchestration](/guides/orchestration).
