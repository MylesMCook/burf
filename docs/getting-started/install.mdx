Burf has two halves: `burfd`, the daemon on each Linux or macOS box,
and the Burf app with the `burf` CLI on your laptop. This fork is a preview:
build it from source. Signed downloads, a Homebrew cask and an application
update feed are not available.

<Callout title="Compatible with Berth">
  `berth` and `berthd` are retained aliases. Existing `.berth` state,
  `BERTH_*` variables, service identities and `berth://` links stay compatible.
</Callout>

## What you need

On the box (Linux, or macOS; amd64 or arm64):

- `git` and `tmux` (on a Mac, `brew install tmux`; on Debian or Ubuntu,
  `sudo apt install tmux`)
- `curl` or `wget`, and `tar`, for the installer
- a [Tailscale](https://tailscale.com) address, unless you tell berthd to
  listen elsewhere (see [where berthd listens](/getting-started/add-a-box#where-berthd-listens))

Before an agent starts, the app asks the box what it has. A box without
tmux, or without the agent's CLI, gets a card with the command that installs
it, typed out for you to run (on this Mac, **Copy and open Terminal**), and
**Check again**; nothing is created until it's there. berthd also finds a
Homebrew tmux (`/opt/homebrew/bin`, `/usr/local/bin`) when launchd starts it
without those on its `PATH`.

On your laptop: macOS, Windows x64, or the x86-64 [Linux alpha](#linux-alpha).
See [build from source](#build-from-source) and the
[Windows build guide](/contributing/windows) for prerequisites and limits.

## Put berthd on a box

The fork installer downloads only fork-owned releases. If none is published,
it stops and prints the build-from-source alternative. Run it on the box
as the user your agents will run as (it needs no root):

```sh
curl -fsSL https://raw.githubusercontent.com/MylesMCook/burf/main/site/install.sh | sh
```

```text title="Example output"
==> Downloading berthd (latest, linux/amd64)
  verified against checksums.txt
==> Checking this machine
  service: /home/me/.config/systemd/user/berthd.service
  listens on: 100.101.102.103:7444
==> Installing berthd v0.1.0 to /home/me/.local/bin/berthd
==> Starting the service
  Installed /home/me/.config/systemd/user/berthd.service; berthd is serving on 100.101.102.103:7444.
  Agent integrations (hooks for needs-you, working and done; Burf's skills):
    Claude Code: skills in /home/me/.claude/skills; hooks added in /home/me/.claude/settings.json
    Not found: Codex, Cursor Agent. After installing one, run: /home/me/.local/bin/berthd integrations install codex|cursor

berthd v0.1.0 is running. Paste this link into Burf on your laptop
(Add a box). It works once, for ten minutes:

  berth://100.101.102.103:7444?code=…&fp=…

Or on your laptop:  burf pair 'berth://100.101.102.103:7444?code=…&fp=…'

Your laptop will dial 100.101.102.103:7444. A new link any time: berthd pair
```

It downloads the latest `berthd` for the box's platform, checks it against
the release's `checksums.txt`, puts it in `~/.local/bin`, and runs
`berthd install`. That sets berthd up as a user service (systemd on Linux,
launchd on macOS) and installs the hooks that report agents' state (needs
you, working, done) for the agent CLIs it finds on the box; `--no-integrations`
skips them, and [first agent](/getting-started/first-agent#let-the-box-report-agent-state)
covers one you install later. A box with no tailnet address gets a question
before berthd listens on every interface. The options, and running it again
to upgrade, are in [add a box](/getting-started/add-a-box#with-the-install-command).

Keep the link it prints for [pairing](#pair-your-laptop-with-the-box).

Rather not run anything on the box? Once the CLI is on your laptop,
`burf add ssh me@my-box` installs berthd over SSH and pairs in one step:
see [over SSH](/getting-started/add-a-box#over-ssh).

## Install the app

Build the app from this fork; see [build from source](#build-from-source).
`make app-build` produces an unsigned local `Burf.app` and disk image.
No signed/notarized Burf release or Homebrew cask is advertised here.

The app carries the `burf` CLI (with the `berth` alias), the Linux builds of `berthd` that
`burf add ssh` and `burf upgrade` upload, and a `berthd` for the Mac itself
(`Contents/Resources/berthd`) for
[Use this Mac](/getting-started/add-a-box#this-mac), so there is nothing else
to install on the laptop. When the [laptop agent](#start-the-laptop-agent)
isn't running, the app offers to start it.

While no box is paired, it opens on a short setup that gets you to a running
agent in about a minute. Its first choice is **Start on this Mac**: Burf
installs the `berthd` it carries and pairs with it, with no terminal (see
[this Mac](/getting-started/add-a-box#this-mac)); agents then run while the
Mac is awake, and you can add a server later. Then **Use the sample** makes
a tiny sample project (`hello`, a Node web server and its test, from
[`examples/hello`](https://github.com/MylesMCook/burf/tree/main/examples/hello))
in `~/work/hello`, or add one of your own; and the composer opens with a
small first task written for the sample: press Enter and the first agent
starts in a worktree of its own. **Connect a remote box**, beside **Start on
this Mac**, adds a server instead (with the link the installer printed, over
your tailnet, or over SSH). With a box already paired, it opens straight to the main
window.

### Updates

Automatic application updates are disabled: the updater public key and
endpoints are empty. No upstream feed or signing identity is used. Replace a
local preview only with a build you intentionally install; the app view and
the box's running sessions are separate processes.

After an update with something new to try, a note at the foot of the
sidebar opens **What's new**: the release's highlights one at a time, each
with **Show me** to go there or the keys that do it. A new install doesn't
get it. **Settings → About → What's new**, or "What's new" in ⌘K, opens it
again.

### The berth command

To use `burf` in a terminal, open **Settings → General** in the app and,
under **Command line**, click **Install** next to **The burf command**. It
asks first, then links `~/.local/bin/burf` to the copy inside the app
(`Burf.app/Contents/MacOS/burf-cli`), so the command updates with the
app. If `~/.local/bin` isn't on your `PATH`, add it
(`export PATH="$HOME/.local/bin:$PATH"` in your shell's profile); these
pages may also use the compatible `berth` alias. `burf help` lists every command.

### Linux (alpha)

The Linux app is an **alpha**: x86-64 only, built on Ubuntu 22.04 with
WebKitGTK, and less tested than the Mac app. Its sidebar and **Settings →
About** say **Alpha**, and About has **Report a Linux bug**, which opens a
GitHub issue; please paste **Copy diagnostics** into it.

Linux desktop behavior was imported from upstream; fork-owned AppImage and
.deb release distribution and updater feeds remain deferred. Build locally
with the existing Tauri toolchain rather than downloading upstream binaries
as Burf. A locally packaged AppImage needs FUSE 2, or
`--appimage-extract-and-run`; packaged applications keep the `berth://` scheme.

Like the Mac app, it carries the `burf` CLI, the Linux `berthd` builds and
tmux, and a `berthd` for this computer. It copies them to
`~/.local/share/berth/app/` on its first launch and after each update, and
runs the agent from there, because an AppImage's own files go away when it
quits; **Settings → General → The burf command** links `~/.local/bin/burf`
to that copy. **Start at login** makes the agent a systemd user service
(`berth-agent.service`); without systemd's user session, the app starts the
agent on its own instead, and it runs until you log out.

What works differently, or not yet, on Linux:

- **Keys.** Ctrl stands in for ⌘, and the app shows its keys that way. In a
  terminal, Ctrl and a letter belong to the shell (Ctrl+W, Ctrl+D, Ctrl+K…):
  add Shift for the app's (Ctrl+Shift+T, Ctrl+Shift+K), and Ctrl+Shift+C and
  Ctrl+Shift+V copy and paste. There is no menu bar.
- **Browser tabs** show the page in a WebKitGTK view laid over the app, as
  the Mac app does with WebKit. **Inspect** opens WebKit's inspector docked
  inside the tab (its own button undocks it). The Console and Network drawer
  works as on the Mac.
- **Title bar.** Your window manager's, with no traffic lights; the window
  title ends in "(alpha)".
- **Wayland.** WebKitGTK runs natively on Wayland. With an NVIDIA GPU the
  app turns off WebKit's DMA-BUF renderer, which leaves the window blank
  there; if the window is still blank, try
  `WEBKIT_DISABLE_COMPOSITING_MODE=1`.
- **arm64** has no build yet.

### The CLI without the app

Build with `make all` on Linux or macOS. It produces `burf` and `burfd`
plus compatible `berth` and `berthd` aliases in `bin/`. Keep the Linux daemon
resources beside the CLI for remote installation and upgrades. Windows
builds use the [Windows build guide](/contributing/windows).

Keep them together: `burf add ssh` and `burf upgrade` look for
`berthd-<os>-<arch>` beside their own executable.

## Pair your laptop with the box

Paste the link the installer printed into the app (**Add a box**; pasting
all of the output is fine), or:

```sh
burf pair 'berth://100.101.102.103:7444?code=…&fp=…'
```

The link works once and expires after ten minutes; `berthd pair` on the box
prints a new one. From here on the laptop talks to the box over pinned
mutual TLS. More in [add a box](/getting-started/add-a-box#with-a-pairing-link).

## Start the laptop agent

The CLI and the app are clients of the **laptop agent**, a background process
that holds the connection to every box (see [the laptop agent](/concepts/laptop-agent)).
Any command that needs it starts it (`burf boxes`, for one). To have it
start at login and come back after a crash, install it as a service
(launchd on macOS, a systemd user unit on Linux):

```sh
burf agent install     # burf agent status | uninstall
```

If the agent isn't running when the desktop app opens, the app offers to
start it: **Start the Burf agent** runs `burf agent start`, and ticking
**Start at login** first runs `burf agent install` instead. Nothing is
installed unless you tick it. The app runs only the copy of `burf` it
carries, and only while it is signed by the same team as the app (see
[the security model](/concepts/security#on-the-laptop)). A dev build
(`pnpm tauri dev`) runs `BERTH_CLI` when set, then the repository's
`bin/burf` when there is one, and otherwise `burf` from `~/.local/bin`,
`/opt/homebrew/bin` or `/usr/local/bin`. Without any of them, the app shows
the command to run in a terminal (`burf status`) and connects as soon as
the agent is up.

## Optional: shorter URLs

Every port on a box has a private URL like `http://3000.my-box.localhost:1377/`.
On a Mac, you can drop the `:1377`:

```sh
burf setup port80      # asks for your admin password once; --remove undoes it
```

It redirects port 80 to 1377 on this computer. On Linux, grant the agent
`CAP_NET_BIND_SERVICE` instead.

## Check everything

```sh
burf doctor            # this computer: the agent, URLs, networks, boxes, agent tools
burf doctor my-box     # a box: git, tmux, cloudflared, agents, where it listens
```

Each check that fails says how to fix it.

## Build from source

For working on Burf, or a laptop the release doesn't cover. You need
**Go 1.27** for `berth` and `berthd`, and **Node 22, pnpm and Rust** for
the desktop app.

```sh
git clone https://github.com/MylesMCook/burf
cd burf
make all
```

`make all` puts the commands and compatible resource names in `bin/`:

| File | What it is |
| --- | --- |
| `bin/burf`, `bin/berth` | The laptop CLI and background agent, for this computer |
| `bin/burfd`, `bin/berthd` | The box daemon, for this computer |
| `bin/berthd-linux-amd64`, `bin/berthd-linux-arm64` | The box daemon for Linux boxes |

Where these pages write `burf`, run `bin/burf` from the clone, or use the
compatible `bin/berth` alias, or put `bin/` on your `PATH`. Then run the app from the clone:

```sh
cd app
pnpm install
pnpm tauri dev
```

It runs the clone's `bin/burf` for the laptop agent (with the legacy
`bin/berth` alias retained). `make app-build`
builds `Burf.app` and its disk image, with the CLI and the Linux daemons
inside, under `app/src-tauri/target/release/bundle/`.
