Berth has two halves: `berthd`, the daemon on each box your agents run on,
and on your laptop the `berth` CLI and the desktop app. Today you build both
from the repository, and `berth add ssh` puts the daemon on a box for you.

## What you need

On your laptop (a Mac, or Linux):

- **Go 1.27** for `berth` and `berthd`
- **Node 22 and pnpm** for the desktop app and plugins
- **Rust** for the app's Tauri shell
- `ssh` access to the box, as the user your agents will run as

On the box (Linux, or macOS; amd64 or arm64):

- `git` and `tmux`
- a [Tailscale](https://tailscale.com) address, unless you tell berthd to
  listen elsewhere (see [where berthd listens](/getting-started/add-a-box#where-berthd-listens))

## Build Berth

```sh
git clone https://github.com/sean-brydon/berthd
cd berthd
make all
```

`make all` puts four files in `bin/`:

| File | What it is |
| --- | --- |
| `bin/berth` | The laptop CLI and background agent, for this computer |
| `bin/berthd` | The box daemon, for this computer |
| `bin/berthd-linux-amd64`, `bin/berthd-linux-arm64` | The box daemon for Linux boxes |

Keep the Linux daemons next to `berth`: `berth add ssh` and `berth upgrade`
look for `berthd-<os>-<arch>` beside their own executable. These pages run
commands from the clone as `bin/berth`; put `bin/` on your `PATH` if you'd
rather type `berth`. `bin/berth help` lists every command.

## Put berthd on a box

One command on the laptop installs berthd on the box over SSH, starts it as
a service and pairs this laptop with it:

```sh
bin/berth add ssh me@my-box --name my-box
```

```text title="Example output"
Using your SSH agent
Checking me@my-box…
Installing berthd-linux-amd64 (9 MB)…
  Installed /home/me/.config/systemd/user/berthd.service; berthd is serving on 100.101.102.103:7444.
Paired with my-box at 100.101.102.103:7444. SSH is no longer needed for this box.
```

`--name` is what Berth calls the box (by default, its hostname); these pages
call it `my-box`. Berth puts the daemon in `~/.local/bin/berthd` on the box,
and from here on the laptop talks to it over pinned mutual TLS: Berth itself
never needs SSH for this box again. The other flags, a Mac box, and a box
with no tailnet address are in [add a box](/getting-started/add-a-box#over-ssh).
To see agents' state (needs you, working, done), the box also needs the
agent hooks, a one-line step in [first agent](/getting-started/first-agent#let-the-box-report-agent-state).

If berthd is already running on the box, run `berthd pair` there instead
and paste the link it prints into the app (**Add a box**), or:

```sh
bin/berth pair 'berth://100.101.102.103:7444?code=…&fp=…'
```

The link works once and expires after ten minutes.

**Once the first release is out**, the box side also takes one line, run on
the box itself: `curl -fsSL https://berthd.app/install | sh` installs berthd
and prints a pairing link to paste into the app (see
[the install command](/getting-started/add-a-box#with-the-install-command)).

## Start the laptop agent

The CLI and the app are clients of the **laptop agent**, a background process
that holds the connection to every box (see [the laptop agent](/concepts/laptop-agent)).
Any command that needs it starts it, as `berth add ssh` just did. To have it
start at login and come back after a crash, install it as a service
(launchd on macOS, a systemd user unit on Linux):

```sh
bin/berth agent install     # berth agent status | uninstall
```

The desktop app talks to the agent but never starts it. If the app says "The
Berth agent is not running", run `bin/berth status` or
`bin/berth agent install` in a terminal; the app connects as soon as it is up.

## Run the desktop app

```sh
cd app
pnpm install
pnpm tauri dev
```

While no box is paired, it opens on a short setup: add a box (over SSH, or
with a pairing link), add a repository on it, and start your first agent.
With a box already paired, it opens straight to the main window.

## Optional: shorter URLs

Every port on a box has a private URL like `http://3000.my-box.localhost:1377/`.
On a Mac, you can drop the `:1377`:

```sh
bin/berth setup port80      # asks for your admin password once; --remove undoes it
```

It redirects port 80 to 1377 on this computer. On Linux, grant the agent
`CAP_NET_BIND_SERVICE` instead.

## Check everything

```sh
bin/berth doctor            # this computer: the agent, URLs, networks, boxes, agent tools
bin/berth doctor my-box     # a box: git, tmux, cloudflared, agents, where it listens
```

Each check that fails says how to fix it.
