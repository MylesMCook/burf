Releases are on [GitHub](https://github.com/sean-brydon/berthd/releases).
The Mac app [updates itself](/getting-started/install#updates); a box
upgrades with `berth upgrade BOX`, or by running the
[install command](/getting-started/add-a-box#with-the-install-command)
again.

## Unreleased

- **Worktree URLs work on a Mac's own box, and in the Browser tab.** On
  this Mac's box, `http://WORKTREE.LOCATION.BOX.localhost:1377/` said "not
  found" for a dev server started in the worktree (`npm start` on 3000), since
  the box only placed a server by its port, and terminals never got `PORT`.
  The box now reads each server's folder on macOS too, as Linux boxes always
  did, and a worktree's terminals and agents get `PORT=$BERTH_PORT` unless
  the project sets it. A URL with nothing running yet says so and how to
  start it, and a server started a moment ago opens at once. Separately, the
  release app's browser panes stayed blank on every `http://…localhost` page:
  macOS App Transport Security refused plain http in the bundled app (never
  in `pnpm tauri dev`); Berth.app now allows it for localhost names only.
  When terminals fall back to xterm.js, the app says why once, with Copy
  details, in Settings → Terminal, and in `berth doctor`. Boxes and the app
  need the update. [Project config](/guides/project-config#services).

## v0.3.5

October 5, 2026.

Agents start however long the prompt, and on a fresh Mac.


- **Long prompts start.** A task or session whose prompt was over about
  16 KB failed with "tmux new-session: ." and its worktree was removed: the
  command went on tmux's command line, which tmux refuses. Each session's
  command now lives in a file only you can read, which its login shell
  runs, so a prompt can be up to a 2 MB request (the agent itself takes its
  first one as one argument: up to 128 KB on Linux, about 1 MB on a Mac,
  and a longer one is refused up front, saying so). A long message sent to
  a running agent goes through tmux's stdin, whole. Every tmux failure now
  says why (its exit status, or a timeout), never an empty reason. Boxes
  need an upgrade. [Sessions](/concepts/sessions-and-agents#sessions).
- **This Mac finds Homebrew's tmux.** The Mac's own box runs under launchd,
  whose bare PATH hid `/opt/homebrew/bin`, so no agent could start there.
  berthd now looks for tmux in Homebrew's folders too, and its launchd
  plist carries your login shell's PATH (with Homebrew's and `~/.local/bin`);
  the agent rewrites an older plist on its next start. `berthd doctor` says
  how to install tmux on that system.
- **Missing tmux or agent CLI gets a card, not a failure.** Starting an
  agent on a box without tmux or the agent's CLI shows how to install it:
  onboarding and ⌘N show the command (`brew install tmux` on a Mac, with
  Homebrew first if needed; the package manager on Linux), **Copy and open
  Terminal** on this Mac, and **Check again**. Nothing is created until
  it's there.

## v0.3.4

October 5, 2026.

Two worktrees side by side, nineteen themes, a chat that keeps every
turn, and browsers that show you the page.


- **Fix a blocked agent's browser from Berth.** On Ubuntu 24.04, whose
  sandbox setting stops Chromium starting, the browser pane marks the
  agent's browser **blocked** and Settings → Boxes shows why, with two ways
  out: **Fix it** opens a terminal on the box with the `sudo sysctl` command
  typed for you to run (Berth never sees your password) and clears once the
  box allows it, or **Run without Chromium's sandbox**, a per-box setting
  that needs no restart. An agent that hits it is told to ask you, and
  `berthd doctor` says the same. Boxes need an upgrade.
  [Agent browser](/guides/agent-browser#when-ubuntu-blocks-it).
- **The browser tab is your browser.** A browser pane always shows the
  worktree's page in a real browser on your laptop, through its proxy; the
  agent's browser on the box shows only while an agent drives it, behind a
  clearly marked **Agent's view · live**, and now shows the page at once
  rather than after its next repaint (most still pages never drew). URLs
  the box writes with its own name (`$BERTH_URL`, `devbox` where you paired
  it as `devl`) open too, a redirect to another port on the box's
  `localhost` goes to that port, and a server macOS can't name counts as
  the worktree's dev server again. Boxes and the laptop agent need an
  upgrade. [Agent browser](/guides/agent-browser#watching-it).
- **The chat keeps every turn.** A prompt with something pasted in it
  (Claude Code 2.1 writes those with a new closing tag) was left out of the
  chat entirely; it now shows as typed. A chat also lost or jumbled turns
  when the box read the conversation afresh (after a box upgrade, or once
  no one had looked at it for ten minutes) or a long chat let its oldest
  live turns go while older ones were loaded: items are now named by where
  they are in the agent's record, so the chat keeps what it showed, reads
  what it missed in between, and turns read back after being hidden come
  back on their own. `/compact` reads as one divider. Boxes need an upgrade.
- **Worktrees side by side (Labs).** Two or more worktrees share one tab
  strip as tab groups: ⌥-click one in the sidebar, drag it onto the strip,
  or choose "Add to tabs beside…". Each group has its name and colour;
  click it to fold it, right-click to colour or close it (its agents keep
  running). ⌃⇧⇥ and ⌃⌥⇥ step between groups, ⌘1–9 count across the strip
  and ⌘⇧W closes the group in front (with one, the window). A tab can show
  panes of two worktrees too: **⌘⌥D** picks a worktree, then one of its
  agents, its page, its diff or a new terminal, and puts it beside the
  focused pane; dragging a worktree onto a pane's edge splits its agent in.
  Run, ⌘T, ⌘⇧B, the + menu, the palette and plugins act in the focused
  pane's worktree. With one worktree open nothing looks different.
  [More](/guides/labs#worktrees-side-by-side).
- **Scrolling keeps up.** The wheel over a terminal now reaches the agent
  in batches, one per redraw, rather than one report per wheel event. A
  trackpad flick through a long Claude Code thread queued dozens of
  full-screen redraws behind each other, and over a slow connection to the
  box the view kept scrolling for seconds after you stopped; now it stops
  within a redraw, the same distance down. Drawing a whole new screen in
  the terminal also takes half the time it did.
- **Nineteen more themes.** Ports of popular VS Code themes: Dracula, One
  Dark Pro and One Light, Catppuccin Mocha and Latte, Tokyo Night, Nord,
  GitHub Dark, Dark Dimmed and Light, Gruvbox, Solarized, Rosé Pine and
  Dawn, Night Owl and Night Owl Light, and Kanagawa Wave, each from its own
  palette for the app, the terminal and code, nudged only where text would
  be too faint to read. Settings groups them Berth, Dark and Light, with a
  search, and **Match system** can use any light and dark pair.
  [Themes](/guides/themes) lists them and how to make your own.
- **Code in replies is coloured.** A code block in an agent's reply is now
  syntax-highlighted like the app's diffs, in the theme's own colours, by
  its fence's language (or a guess). It colours in after it draws, off the
  main thread, without moving; Copy still takes the plain code.
- **Smaller fixes.** A long reply scrolls inside the reply box instead of
  pushing the chat away, and text size (⌘+ / ⌘−) now reaches the chat
  itself, its code and its edits, not just the UI around it.

## v0.3.3

October 5, 2026.

The chat takes on the rest of what a terminal does: Claude's questions,
its artifacts, its edits as diffs, and dev servers in tabs of their own.


- **Archiving follows through.** Archive or remove a worktree from the
  sidebar, zen, the launcher or the Worktrees table and it shows as
  "Archiving…" (dimmed, nothing to open) while the repo's archive script
  runs, then leaves the sidebar, the table and its open tabs as soon as the
  box reports it gone; its sessions stop with it. If the script fails, the
  worktree comes back with the script's output under Details. The app used
  to say "Archived" at once and keep showing it. Boxes need an upgrade for
  the session stop and the script's output.
- **A worktree left locked archives.** A `git worktree add` that was cut off
  leaves git's own "initializing" lock, and git then refuses to remove the
  worktree. The box now unlocks and removes those, cleans up after an add
  that fails, and still leaves alone a worktree a person locked, saying how
  to unlock it. Boxes need an upgrade for it.
- **Details opens.** "Details" on an error toast did nothing when clicked.
  It now opens the full output (git's, a script's) in a dialog with Copy,
  everywhere it appears.
- **Artifacts in the chat.** A page Claude publishes on claude.ai with its
  Artifact tool shows as a card where it happened, with Open, and a
  "3 artifacts" chip at the right of the reply box's controls lists them
  all, newest first: open one, copy its link, or show it in the chat. A
  page published again is marked updated. Boxes need an upgrade for it.
- **Claude's questions, answered in the chat.** When Claude asks several
  questions at once (AskUserQuestion), the chat used to answer only the
  first and then hang. Now it shows the whole form: each question with its
  options, one pick or several, room for your own words, back and next, and
  a review with Submit. The box fills in Claude's own form key by key,
  checking its screen as it goes; if anything doesn't match, it stops and
  Claude's screen opens under the chat to finish there. Answers stay in the
  conversation as what you picked. Boxes need an upgrade for it.
- **Services in a terminal tab.** A service with `"terminal": true` (in a
  kit, `.berth/config.json` or a box's own config, with an optional
  `"title"`) runs in a terminal of its own, which opens as a tab named after
  it when its worktree does, so a dev server's output is right there.
  Ctrl-C in the tab stops it, and Start, in the tab or anywhere else, runs it
  again in the same tab. Closing the tab only hides it; "Running in" and the
  Run menu have Show terminal. Boxes need an upgrade for it.
- **Drag tabs into splits.** Drag a tab from the top bar over a pane and
  drop it on an edge to split that pane right, left, up or down, with an
  outline showing where it lands; drop it between tabs to reorder. A pane
  drags by its header beside another pane, onto another's middle to swap
  them, or onto the strip to become a tab of its own. Nothing restarts:
  terminals and agents keep their sessions. A tab's menu has Split right
  and Split down, and a pane's ⋯ menu has Move to a new tab.
- **Edits in the chat look like the Diff panel.** An agent's edit opens
  highlighted, in the same renderer as the Diff panel, numbered by the
  file's own lines; Write and MultiEdit too, and the file's uncommitted
  diff beside it still takes comments. Unified in the chat's column, split
  where the pane has room (it remembers), and a long edit folds to Show
  all. The renderer loads the first time you open an edit, never before.
  Boxes need an upgrade for the line numbers; older ones count from 1.
- **Chat backgrounds and width.** Settings → Appearance → Chat background
  puts a quiet background behind conversations, in zen too, drawn in your
  theme's colours: patterns (chart contours, a dot grid, a nautical grid,
  soft waves), dithered gradients (Dawn, Dusk, Deep sea) and harbour
  scenes. A picture of your own, picked, dropped or generated with Codex on
  your Mac (it shows the exact command and runs only when you press
  Generate), lands dithered in the theme's ink. Strength, Dither and Tone
  shape it; Advanced can show a picture as it is. Chat → Width sets how wide
  conversations run, from Narrow to Full. A pane's ⋯ menu has Chat
  background….
- **One corner radius.** Cards in the chat, the task list, notices and the
  agent's own screen take the reply box's radius; bubbles keep their own.
- **Zoom with ⌘+ and ⌘−.** View → Zoom in (⌘+ or ⌘=), Zoom out (⌘−) and
  Actual size (⌘0) make the app's text bigger or smaller, from 11 to 20px,
  with a moment's readout of the size; it's kept, and Settings →
  Appearance → Text size shows it. With a terminal focused they size the
  terminal's font instead, and ⌘0 puts it back to 13px.

## v0.3.2

October 5, 2026.

- **Built-in plugins on a fresh install.** The release's content policy
  kept the app from reading its own list of built-in plugins, so a new
  install had none: Diff, Changes, Pull request, Notes and the rest. Dev
  builds skip that policy; CI now checks it.
- **New task with a line break** (⌘N) starts its agent. The box couldn't
  read back a session whose prompt had a line break, so it removed the
  worktree it had just made and said "It's gone".
- **Pasted screenshots upload fast.** A pasted image over 1 MB or 2000 px is
  shrunk first (a 4 MB screenshot goes up as about 30 KB), files go up as
  raw bytes rather than base64, and the chip shows progress, its size, and
  Retry if it fails. Chips sit inside the composer.
- **Replies with a paste show where they were sent.** Claude Code records a
  paste wrapped in `<pasted_content>` tags; the chat dropped such a reply,
  and it showed below the answer instead. Its tags no longer show either.
- **A reply sent while the agent works** says it hasn't read it yet:
  "Sent · Claude reads it at its next step".
- **Diff and Pull request follow the branch** when the agent switches,
  commits or rebases mid-turn.
- **Live text** read off the agent's screen looks like the reply, not a
  quote.

- **Labs is on by default**: the harbour home, agents as conversations,

## v0.3.0

October 4, 2026.

The chat grows up: it stays in step with the agent's terminal, takes
everything the terminal takes, and stays fast on long conversations.

- **One chat per agent, in step with its terminal.** Several agents in one
  folder keep separate chats; a new agent never shows another's. A message
  sent mid-turn shows before its reply, the running step and the agent's
  own status ("Running pnpm test · 18s", "Seasoning… · 9m") show live, and
  its words show from the screen before the transcript has them.
- **Replies as Markdown.** Headings, tables and code render as the
  terminal shows them, with less noise: the steps between replies fold.
  Text selects and copies; Copy takes the Markdown.
- **Open a tool call** to see what the terminal shows: the full command and
  its output, an edit's exact change
  (`GET /v1/sessions/{name}/transcript/tool/{id}`).
- **Everything the terminal takes.** `/` lists the agent's built-in and
  custom commands, skills and plugins; `@` files, `!` shell. Screens of
  the agent's own, such as `/model`'s picker, open inline and fold away.
- **Chat controls.** Stop, the permission mode and model chips, the agent's
  task list, context meter, background shells, and cards for API errors,
  limits and an agent that exited mid-work.
- **History and scale.** Older turns load as you scroll up, helpers'
  (subagents') own chats open from Crew, ↑/↓ recalls prompts, ⌘F searches
  the chat, and Fork and Rewind start over from any prompt. 5,000 items
  paint in about 0.3 s and scroll at 60 fps.
- **Paste or drop images and files** for an agent on a remote box, in the
  chat or its terminal; they upload to the worktree's `.berth/attachments`.
- **What's running in a worktree** sits under the composer, with names and
  Open in tab, and plugins can add a section with `addWorktreeSection`.
- **Diff panel.** A worktree's whole branch diff, its uncommitted changes,
  or both, drawn with [`@pierre/diffs`](https://diffs.com).
- **Pull request picks.** Pick failing checks, reviews and comments on a
  PR and send them to the worktree's agent, or copy them.
- **Closing a tab stops its agent**, with a moment to undo, and a new tab is
  always a new session.
- **Zen on ⌘.** from the menu bar, rename and archive from zen, and the wheel
  scrolls a full-screen agent's terminal instead of cycling its prompts.

- **What happens to your message.** A reply sent while the agent works
  shows as queued in the conversation, with **Send now** and **Cancel**, and
  the reply box says whether Enter sends or queues. The box lists, cancels
  and sends held prompts (`GET`/`DELETE /v1/sessions/{name}/queue`).
- **Approvals from Claude Code's hooks.** A permission reads "Claude wants
  to run `pnpm test`" with Claude's reason, from its `PermissionRequest`
  hook rather than the screen, with Allow, Always allow and Deny matched to
  its menu. The request stays in the box's private ledger, never in events.
- **See the work, comment on it.** An edit in the conversation opens to its
  diff (`GET /v1/sessions/{name}/diff`), and lines take comments there and
  in Review, sent to the agent as one short prompt.

## v0.2.0

October 4, 2026.

Orchestration rebuilt on the box: it keeps going while your laptop sleeps,
survives berthd restarts and upgrades, and costs your agents as few tokens
as it can.

- **Turns, not guesses.** Every prompt Berth sends gets a turn ID, and
  waits, loops and flows wait on that turn, not on the clock or the folder.
  Each session is tracked on its own, so a reviewer beside an agent no
  longer ends the agent's wait. Hook events go through a numbered journal
  (`GET /v1/events?since=`), are kept while berthd is down, and are never
  dropped in a burst. Codex, Cursor, Gemini and OpenCode report their
  state through their own hooks. See [sessions and agents](/concepts/sessions-and-agents).
- **Quieter "needs you".** Claude's idle reminder no longer counts as a
  question, an approved permission clears "waiting", and nothing Berth sends
  (broadcast, the queue, loops) types into an agent that is waiting on you.
- **Durable runs.** Loops, reviews, hand-offs, broadcasts and flows run on
  the box from a journal: they keep going while the laptop sleeps and
  resume after berthd restarts, never sending an agent a prompt twice.
  `berth run …`, `berth runs`, and `berth loop` as a run; gates you decide
  from the app, the CLI or the phone; box-wide caps and per-run budgets.
  See [runs](/guides/runs).
- **Try N ways.** Several agents, or models, try one task in their own
  worktrees, on one box or several; a check verifies them, a headless judge
  ranks them, and Review's Compare lets you pick one for a draft PR.
- **Triggers v2.** Issue labels and assignees, signed webhooks, and an
  Auto-fix this PR toggle; a GitHub item arriving while a flow runs waits
  for it instead of being dropped, and comment text reaches an agent
  labelled as untrusted, from the authors you allow. See
  [automations](/guides/automations).
- **Handoff packets** and native fork or resume; **headless agents** in
  tmux; **`berthd mcp`** for agents. The app's flows for every box are gone:
  commit such a flow to the repository's `.berth/config.json` or its kit.
- **A browser for your agents.** Each worktree's agent can open its own dev
  server at the URL you see (`BERTH_URL`) in a headless Chromium on the box,
  confined to that worktree's ports, and act on it in a few hundred tokens a
  step. Watch it live, pick an element to send it, and see its screenshots
  in Review. On Ubuntu 24.04, allow Chromium's sandbox or opt out with
  `BERTH_BROWSER_NO_SANDBOX=1`. See [agent browser](/guides/agent-browser).
- **The agent's conversation**, read from Claude Code's or Codex's own
  transcript (`GET /v1/sessions/{name}/transcript`), for a calmer view of
  what an agent is doing. Tool output and thinking are never sent. On a box
  with an older berthd, the view offers to update it in place.
- **Pick a model and effort** for a new agent (`model` and `effort` on
  tasks and attempts, passed to each agent's own flags), so attempts can
  pit models against each other.
- **Labs: a calmer Berth.** Behind a Labs switch in Settings: a harbour home
  with one composer and your agents, a Conversation view beside each
  agent's terminal, and zen (⌘.), which puts the sidebar away. See
  [Labs](/guides/labs).

## v0.1.2

October 3, 2026.

- **Set up a box from your tailnet.** **Add a box** lists the machines on
  this Mac's tailnet, with their OS, whether they are online and which are
  boxes already, and **Set up** installs and pairs one over SSH. Tailscale
  SSH needs no keys, a host key the tailnet vouches for is trusted, and
  check-mode approval opens in your browser. **Sign in to another tailnet**
  lists that tailnet's machines too. `berth discover --json` reports
  Tailscale's state and each machine's Tailscale SSH and host keys. See
  [add a box](/getting-started/add-a-box#on-your-tailnet).
- **The Cal.com kit has its own repository**,
  [berth-kit-calcom](https://github.com/sean-brydon/berth-kit-calcom).
  Kit links to GitHub, GitLab, Bitbucket and Codeberg work without
  `https://` (`berth kit add github.com/me/kit`). See [kits](/guides/kits).
- **Add another computer** with a join link, and **use this Mac as a box**
  without the CLI.

## v0.1.1

October 3, 2026.

- **A signed Mac app.** `Berth-macos-universal.dmg`, one app for Apple
  silicon and Intel, signed with a Developer ID and notarized. It carries the
  `berth` CLI and the Linux daemons. See [install](/getting-started/install#install-the-app).
- **Automatic updates.** The app checks for a new release in the
  background and shows **Restart to update** when one is ready; it never
  restarts by itself.
- **The `berth` command from the app.** **Settings → General → Command
  line** links `~/.local/bin/berth` to the app's copy.
- **Security fixes** from an audit; [the security model](/concepts/security)
  has the whole picture:
  - A repository's committed `.berth/config.json` runs on a box only once
    [trusted there](/guides/project-config#trusting-a-repositorys-config),
    for its exact content.
  - Plugins you install never turn on by themselves, and ask for
    [consent](/guides/plugins#trust-and-consent) pinned to a hash of their
    code.
  - [Flow](/guides/automations#how-values-are-filled-in) values reach
    shell steps as `$BERTH_FLOW_*` environment variables, never as script
    text; webhook values are encoded; secrets show as `[secret]`.
  - Webhooks and phone notifications can't reach loopback, private or
    metadata addresses unless `~/.berth/network.json` on the box allows them.
  - Gates cover every route that changes something and see an origin the box
    can vouch for; revoking a laptop closes its open streams; pairing is
    limited per source address; clones and kit fetches refuse local and
    command transports; kits apply only what you reviewed; project skill
    installs refuse symbolic links.

## v0.1.0

October 3, 2026. The first release.

- `berthd` for Linux and macOS boxes, and the `berth` CLI, for amd64 and
  arm64, with `checksums.txt`.
- One line installs berthd on a box and prints a pairing link:
  `curl -fsSL https://berthd.app/install | sh`. It installs the hooks that
  let Claude Code, Codex and Cursor report their state.
- `berth add ssh` installs and pairs a box over SSH in one step.
- The desktop app, built from source, with the laptop agent startable from
  the app.
