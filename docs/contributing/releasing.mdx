Burf is a fork preview. There is no fork-owned signed application release or
update feed configured. The updater key and endpoints remain empty. Upstream's
Homebrew cask, Linux release/feed jobs, signing identities and release secrets
are not Burf distribution.

## Local builds

Use the repository's existing toolchains and locked dependencies:

```sh
make all
make app-build
```

The macOS app build produces an unsigned local `Burf.app` and disk image.
Windows packaging follows the [Windows guide](/contributing/windows).
Linux desktop platform support is imported, but publishing fork-owned Linux
bundles and feeds remains separate work. Build outputs and daemon resources
retain the legacy names required by existing clients and integrations.

## Verification before publishing

Verify the exact commit used to build the artifacts. Go race tests, frontend
unit/type/build checks, blocking browser acceptance, branding checks and
platform packaging checks are required. Native Windows/Linux execution,
signed-in providers and installed-app upgrades require separate evidence;
cross-builds and synthetic browser fixtures do not establish them.

Fresh installs and upgrades must preserve settings, pairings and running
sessions. Use isolated state and verify a rollback path. The existing Mac
release-acceptance scripts use GUI automation and service supervisors, so
running them is a host-changing action requiring separate authorization.

Do not enable an updater until fork-owned signing and feeds are configured and
verified. Upload and verify signed artifacts before publishing a feed.
Tag pushes, `make publish`, uploads and deployments perform external writes;
source integration does not authorize them.

## Upstream reference

[Shipyard's release guide](https://github.com/cosscom/shipyard/blob/9ae4747452f59f4c51a4b78854cc1b6020d1c674/docs/contributing/releasing.mdx)
describes upstream's own archives, cask, signing and feed workflow. It is a
reference for future Burf release work, not an installation or publication
procedure for this fork. Upstream release history is retained in the
[changelog](/changelog).
