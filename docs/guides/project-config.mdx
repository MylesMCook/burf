A repository's `.berth/config.json`, committed with the code, says how every
worktree of that repository is set up and torn down, which ports,
environment and services it gets, and which agents to offer. It travels with
the repo, so every box does the same.

```json title=".berth/config.json"
{
  "setup": "pnpm install && createdb $BERTH_WORKTREE_SLUG",
  "archive": "dropdb --if-exists $BERTH_WORKTREE_SLUG",
  "ports": 2,
  "env": {
    "DATABASE_URL": "postgres://localhost/$BERTH_WORKTREE_SLUG",
    "NEXT_PUBLIC_WEBAPP_URL": "$BERTH_URL"
  },
  "services": [
    { "name": "web", "run": "pnpm dev --port $BERTH_PORT", "autostart": true },
    { "name": "worker", "run": "pnpm worker" }
  ],
  "agents": [
    { "id": "claude", "name": "Claude Code (Opus)", "command": "claude --model opus" }
  ],
  "hooks": [
    { "on": "worktree.created", "run": "cp ../shop/.env .env" }
  ],
  "flows": []
}
```

Every field is optional; [the config reference](/reference/config) lists
them all with their rules.

## Trusting a repository's config

The file is code: its setup script, services, hooks, flows, `env` and agent
commands all run on the box. So a box runs none of it until someone trusts
it there. Until then the box applies only `ports`, and the app shows
**This repository wants to run …** with every command the file holds, and
**Trust and run it** / **Not now** — in Project settings, and when you create
a worktree (**Trust and create** / **Create without it**). A worktree made
without trust is a plain checkout.

- Trust is per box and per project, and is for the file exactly as you saw
  it: the box keeps the file's SHA-256 hash. When a commit changes the file,
  none of it runs again until it is trusted again.
- A file with nothing but `ports` needs no trust.
- A [kit](/guides/kits) you apply, and the box's own config below, are
  yours, and apply without asking.
- Only trust a repository if you trust everyone who can commit to it.

From a terminal, `berth location config devl/shop` prints what the file
wants and its hash; `--trust HASH` trusts that version, `--untrust` stops it.
The box's API is `POST /v1/locations/{name}/config/trust` with
`{"hash": "…"}` (refused with 409 if the file no longer has that hash) and
`DELETE` on the same path. Both run `before:config.change` gates and announce
`config.changed`.

## Setup and teardown

- `setup` runs right after a worktree is created, in it, through a login
  shell (up to 30 minutes, with its output in a log on the box).
- `archive` runs before a worktree is removed, after its services stop; if it
  fails, the worktree stays.
- Both also get Orca's names (`ORCA_ROOT_PATH`, `ORCA_WORKTREE_PATH`,
  `ORCA_WORKSPACE_NAME`), so setup scripts written for Orca work unchanged.

## Ports and environment

- **Ports.** Every worktree has its own block of ports, stable for its life
  and freed when it is removed: `$BERTH_PORT`, then `$BERTH_PORT_1`… up to
  `ports` of them (at most 10; at least one). Whatever listens on a port in
  the block counts as the worktree's, containers included, and the
  worktree's [private URL](/concepts/projects-and-worktrees#private-urls),
  `http://<worktree>.<location>.<box>.localhost:1377/`, reaches the lowest
  one.
- **Environment.** Everything run in a worktree (setup and archive scripts,
  terminals and agents, `exec`, hooks, flows, services) gets these, then
  `env` with them expanded:

| Variable | Meaning |
| --- | --- |
| `BERTH_BOX` | The box's name for itself |
| `BERTH_LOCATION` | The location, like `shop` |
| `BERTH_ROOT_PATH` | The repository's main checkout |
| `BERTH_WORKTREE_PATH`, `BERTH_WORKTREE_NAME` | This worktree |
| `BERTH_WORKTREE_SLUG` | Like `shop_fix_checkout`, safe for database names |
| `BERTH_BRANCH` | Its branch |
| `BERTH_PORT`, `BERTH_PORT_1`, … | Its ports |
| `BERTH_URL` | The worktree's private URL as you open it on your laptop, such as `http://fix-checkout.shop.devl.localhost:1377` (the main checkout: `shop.devl.localhost`). Use it for an app's own base URL, not `localhost:$BERTH_PORT`, which the laptop never sees |
| `BERTH_BROWSER_PROXY` | The worktree's [browser proxy](/guides/agent-browser#what-it-can-reach), for a browser an agent runs itself |
| `BERTH_KIT_DIR` | Where the project's [kit](/guides/kits) keeps its files, if it has one |

A value in `env` can use `$NAME` for those variables or berthd's own
environment, and can be a [secret reference](/guides/secrets) instead of a
value.

## Services

Services run in each worktree as managed processes that survive the daemon
restarting and come back if they crash, with their output in a log.

- `autostart` ones start when the worktree is created, after setup succeeds.
- All of them stop before the archive script runs.
- A service also gets `PORT` (its worktree's `$BERTH_PORT`) unless `env`
  sets it.
- Start, stop and open them from the app's **Run** menu, or:

```sh
berth service list devl/shop/checkout
berth service start devl/shop/checkout web
berth service log devl/shop/checkout web
```

## Agents

`agents` adds ways to start agents in this repository, or replaces a
built-in one with the same `id` (`claude`, `codex`, `opencode`, `gemini`,
`cursor`). A first prompt goes at the end of `command`, or after
`prompt_flag` if the agent needs one.

## Hooks and flows

- **Hooks** fire only for this repository's events, inside the worktree the
  event is about, with its environment. `before:` gates here can refuse
  actions in this repository. See [hooks](/guides/hooks).
- **Flows** are this repository's automations, on every box that has it.
  See [automations](/guides/automations).

## This box only

Some of it should not be committed: a database password, one box's paths.
Each box keeps its own config for a location, laid over the file (and over
the project's kit, if it has one):

- `setup`, `archive`, `ports` and each `env` entry replace the file's;
- `services`, `agents` and `flows` replace the file's by name or id, and add
  new ones;
- `hooks` add up.

Edit it in the app's Project settings, or `PUT /v1/locations/{name}/config`
on the box. `berth location config devl/shop` shows the effective config
(and what an untrusted file would run); with `--json`, the repository's, the
kit's and the box's layers too.

```sh
berth location scripts devl/shop --setup "make bootstrap"   # just the scripts
berth location scripts devl/shop --clear
```

A box can also give every worktree on it some environment, in
`~/.berth/env.json` (`{"env": {"KEY": "value"}}`), under the project's own.
