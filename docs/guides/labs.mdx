Settings → Labs turns on ideas that are still being tried. They are off by
default, so the app stays as it is for anyone who does not opt in, and they
may change or go away.

## Harbour home

With no worktree open, the workspace is one composer (Labs or not): what
should your agents work on, on which project and box, in a new worktree or
the main checkout. Below it are your agents, who needs you first, then who
is working, then what just finished, and the worktrees you opened lately.
An empty worktree has a composer that starts an agent right there. Labs
adds the harbour above them: a painting of the harbour dissolving into the
page, in a halftone grain, at night in a dark theme, smaller in an empty
worktree.

The harbour is **Home**, the first place in the sidebar. Without Labs that
place is the Agent Dashboard; with Labs the dashboard moves under **More**
(⌘J still opens it, as does **Dashboard** on the harbour).

## Model picker

The composer's agent picker chooses the agent and, where its CLI takes
them, the model and effort (Claude Code's `opus`, `sonnet` and `haiku`, and
its effort levels; Codex's reasoning effort). Default is the CLI's own
default. Pick one and it is a task; pick several agents, one model against
another, or ×2 of each, and it starts [attempts](/guides/runs#attempts),
each with its own model. Which models are offered is set per agent: see
[models and effort](/guides/project-config#models-and-effort).

## Conversation view

Agent panes get a Terminal | Conversation switch. The conversation is the
agent's own transcript as a calm list: what you asked, its replies, tool
calls folded into groups ("Read 5 files"), edits with line counts, and the
helpers it sent out, which also show as **Crew** in the floating panel. A
question shows as buttons for its options; answering types the option into
the agent. A permission reads from Claude Code's own hook ("Claude wants to
run `pnpm test`", with its reason), with **Allow**, **Always allow** when the
agent offers it, and **Deny**, matched to the options on its screen; agents
without hooks fall back to reading the screen.

An edit opens to the file's current diff in the worktree (folded until you
open it), with **Open in Review**. Hover a line to comment on it; comments
also work in Review, and **Send to agent** sends them as one short prompt
(each file and line with your note, never the code around it) that waits
until the agent is idle. Comments are kept on this Mac per worktree until
they are sent or dismissed.

The reply box says what Enter does: **Send**, or **Queue** while the agent
works. A queued reply shows under the conversation ("Queued: sends when
Claude finishes") until the box types it in, with **Send now** (it asks
first if the agent is waiting on you) and **Cancel**. Berth reads Claude Code's and Codex's transcripts on the box
(`GET /v1/sessions/{name}/transcript`); for other agents, or on an older
box, the pane says so and offers the terminal. Settings → Labs chooses
which view agent panes open in.

### Chat controls

Under the reply box sits what you would otherwise read off the agent's
terminal, so the chat can stand in for it:

- **Stop** (or **Esc** in the reply box) while the agent works presses Esc
  for it, as at its terminal. The box waits for the agent to stop, ends the
  turn (Claude Code's hooks say nothing on an interrupt) and the chat shows
  **Interrupted**, with **Continue**.
- **Permission mode**: Ask before edits, Accept edits, Plan, Auto, or
  Bypass permissions (in red) for Claude Code; Codex's approval policy.
  Switching presses Shift+Tab until the agent's screen shows the mode, and
  is refused while it waits on a question (Shift+Tab there would pick an
  option). Bypass is only offered by a session started allowing it.
- **Model and effort**, from the agent's last answer. Picking one types
  `/model` or `/effort`; if Claude Code asks to confirm, its own screen shows
  inline, and the chip says "Switching…" until Claude Code says it switched.
  Claude Code also makes the choice its default for new sessions.
- **Context**: how full the agent's context is ("62%"), from its last
  answer's token use against its model's window (Codex reports its own).
  Above 80% it turns amber and offers **Compact** (`/compact`, queued if the
  agent is working).
- **Background work**: "1 shell running" for shells started with
  `run_in_background` and monitors. Open it to see each one's command and its
  output so far, read from the agent's output file as it grows; finished
  ones stay a few minutes.

The agent's **task list** (Claude Code's TodoWrite or TaskCreate/TaskUpdate,
Codex's plan) docks above the reply box as a checklist that ticks off in
place, with counts; it folds once all is done and can be put away.

Errors are never silent. API errors, usage and rate limits (with when they
reset), a sign-in that expired, failed hooks, a turn that ended on an error
(Claude Code's StopFailure), and an agent whose program ended mid-work each
show as a card with one next step: **Try again**, **Log in at the terminal**,
**Show terminal** or **See why**. A request being retried shows as one
line that updates. A limit shown only on the agent's screen is read from
there.

These need a box with the `controls` capability (berthd from October 2026):
`POST /v1/sessions/{name}/interrupt`, `…/mode`, `…/keys` and
`GET …/controls`; the transcript's `signals` carry the rest.

### History

A chat holds its last 300 items; scroll up and the earlier turns load a
page at a time (**Load earlier messages** above them, **Start of the
conversation** once there are no more), leaving what you were reading where
it was. Only the rows near the view are drawn, so a chat thousands of items
long opens and scrolls as fast as a short one. A chat hidden for a minute
lets its earlier turns go; scrolling up reads them again.

- **Helpers' own chats.** Click a helper in **Crew**, or its name under
  "Sent out 2 helpers", and its conversation opens in a sheet beside the
  chat, read-only and drawn the same way: what the agent asked it, its steps
  folded, each call opening to what it ran and printed. Its siblings are
  tabs at the top; a working helper updates as it goes.
- **Earlier prompts.** In an empty reply box, **↑** and **↓** go back
  and forth through the prompts you sent, newest first, as at a terminal.
- **Find.** **⌘F** with the chat focused finds words in prompts, replies
  and steps' targets, folded steps included (they open to the match). **↵**
  goes to the older match, **⇧↵** to the newer, **Esc** closes it. A terminal
  pane keeps its own ⌘F.
- **Edit and resend, fork, rewind.** Hover a prompt you sent:
  - **Edit and resend** puts its words back in the reply box.
  - **Fork from here** starts a new Claude Code in the same worktree with
    everything said before that prompt, sends the prompt (as you edit it)
    and opens it as a tab, "Fork of …". The original is untouched.
  - **Rewind to here**, while Claude Code is idle, takes it back to before
    that prompt with its own `/rewind`: just the conversation, or the code
    too. The prompt comes back to the reply box to edit and send again.

Fork and rewind work with Claude Code. Claude Code only cuts a resumed
conversation short in print mode, so a fork is a copy of its record up to
that prompt, resumed. Rewind drives `/rewind` on the agent's screen, moving
up its list and checking the highlighted prompt at each step; anything
unexpected (text typed in its prompt, a list that doesn't show the prompt)
backs out with Esc and says why. These need a box with the `history`
capability: `GET …/transcript?before=`, `GET …/subagents` (and each one's
`…/transcript` and `…/tool/{id}`), `POST …/fork` and `POST …/rewind`.

### Commands in the chat

The reply box (and the first-prompt composer) takes everything the agent's
own prompt does, typed exactly as you type it:

- **`/`** at the start lists the agent's commands, fuzzy-matched as you
  type, each with what it is: **Built-in** (`/model`, `/compact`, `/context`,
  `/usage`…, with aliases such as `/cost`), **Custom** (`.claude/commands` in
  the repo and in `~/.claude`), **Skill** (`.claude/skills`) and **Plugin**
  (enabled plugins' commands and skills, `/vercel:deploy`). For Codex, its
  own commands and `~/.codex/prompts` (`/prompts:name`). **↑↓** move,
  **Enter** or **Tab** puts the pick in the box, **Esc** closes; a command
  typed in full sends on Enter.
- **`@`** lists the worktree's files (what git tracks, plus new files it
  doesn't ignore); the pick goes in as `@path`.
- **`!`** runs the rest in the agent's shell, and a badge on the box says
  so. Claude Code 2.1 has no `#` memory shortcut, so a `#` line goes as a
  prompt and the badge says that; `/memory` edits memory.

What a command prints shows in the chat: a one-line answer as a line under
it ("/model ↳ Set model to Sonnet 5.5 for this session only"), longer output
as a card (`/context` as Claude Code's own table, `!ls` as its output), and
`/clear` as a divider where the fresh conversation starts. A skill or custom
command reads as what you asked, followed by the agent's answer.

When the agent shows a screen of its own that the chat can't draw (the
`/model` picker, `/config`, `/resume`, `/permissions`, `/login`, the usage
dialog, a trust or update prompt at start), its **live terminal opens
inline** under the conversation: "Claude Code is showing its own screen —
answer it here". It takes the keyboard, so arrows, Enter and Esc go straight
to the agent, and it folds away once the agent is back at its prompt (or
fold it yourself; the reply box waits until then). Berth spots such a screen
from the agent's screen while it isn't asking a question its hooks describe:
key hints at its foot ("Esc to cancel", "Enter to confirm"), numbered
options, or no prompt where there always is one at rest. Only one terminal
is attached per pane, and only while it shows.

The agent's own commands (`/cost`, `/model`, `!ls`…) start no turn, so they
never hold up a queued prompt or a `berth session send --wait`. These need a
box with the `commands` capability: `GET /v1/sessions/{name}/commands`
(cached a minute, capped at 600) and `GET …/files?q=`. MCP servers' prompts
aren't listed: the agent reads them from each server once it starts.

## Zen

⌘. puts everything but the agents away: no sidebar, tab strip or status
bar, and agents open as conversations. One small switcher at the top left
shows where you are. It lists the sidebar's places in the sidebar's order
(Home, Review, Worktrees, Automations and More, however you arranged them),
then your agents (who needs you first), then worktrees, then Search, Keyboard
shortcuts, Settings and Leave zen. ⌘K searches everything. ⌘. again brings
it all back, and the app remembers which you left it in. In the Mac app, Zen
is also under View in the menu bar.
